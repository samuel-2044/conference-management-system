# Storage (Cloudflare R2)

**Provider:** Cloudflare R2
**Purpose:** Store uploaded documents, slides, papers, and images (speaker photos, avatars, session/conference images).
**Bucket:** `CONFERENCE_IMAGES`

---

## How It Works

1. The frontend uploads a file directly to the Worker (or via a presigned PUT to R2).
2. The Worker stores the object in R2 using a stable `file_key` (e.g. `conferences/<id>/avatars/<uuid>.jpg`).
3. The Worker persists a `documents` row with `file_key`, `file_name`, `file_size`, and `content_type`.
4. The Worker resolves `file_url` on demand:
   - Public objects: a direct R2 `/<bucket>/<key>` URL served via Cloudflare caching.
   - Private objects: a short-lived signed URL generated by the Worker.

No `file_url` is stored long-term; it is computed at request time to avoid stale links.

---

## Naming Convention

```text
<scope>/<entity-id>/<category>/<uuid>.<ext>
```

| Scope     | Example                              |
| --------- | ------------------------------------ |
| users     | `users/<user-id>/avatar/<uuid>.jpg`  |
| speakers  | `speakers/<speaker-id>/photo/<uuid>.jpg` |
| conferences | `conferences/<conf-id>/doc/<uuid>.pdf` |
| sessions  | `sessions/<session-id>/doc/<uuid>.pdf` |

---

## Security

- R2 object keys are server-generated UUIDs — no user-supplied path segments.
- Only authenticated, authorized users can upload or retrieve files.
- Access control is enforced in the Worker via the `permissions` / `role_permissions` tables.
- Egress to R2 from Cloudflare Workers/Pages is free (no bandwidth cost).
